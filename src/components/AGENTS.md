# UI rules (windows, scroll, calendar)

- Window overlays (dialog, alert-dialog, sheet, drawer bases in `src/components/ui`) carry `data-dialog-overlay`; closing overlays never fade and `html` keeps `scrollbar-gutter: stable` (`src/styles.css`), so opening/switching windows never flashes the page behind. New windows must use these bases.
- Scroll lives only in the content quadrant: window bases split children into fixed header/footer and a scrolling `WindowBody` (`src/components/ui/window-body.tsx`); the shell never scrolls, so the bar never reaches the X or the header. Scrollbar standard is "fio de seda" (`src/styles.css`): 2px thumb at `--foreground` 34%, always visible while there is content to scroll, 4px on hover; mobile overlay bars (`src/lib/scroll-indicators.ts`) use the same tokens. Never style per-component scrollbars.
- Conversations escalated to a human never auto-open the full Atendimento window: they become `QuickChatBubbles` beside the floating button (stacked when several) that expand into an in-place mini-chat; only an explicit push click opens the full window.
- Playbook hides empty manually-editable optional rows (only `STANDARD_MANUAL_FIELDS` stay visible) and offers them via "Adicionar campo"; "Replicar" only shows on manually-edited rows, never on listing/scrap data such as house rules.
- The dashboard occupancy calendar keeps the full date range but is NOT a `<table>`: each property is a flex row (sticky name column + fixed-width track) where every stay/manual block is ONE absolutely positioned bar (`computeBarSegments`, `src/lib/occupancy-bars.ts`), the vertical grid is a single repeating background, and only day headers/touch cells near the viewport are rendered (column virtualization in `OccupancyPanel`); no CSS scroll snap. A dynamic-`colSpan` table forced WebKit to relayout the whole grid per scroll frame and blanked the paint on iOS; rendering every day froze browsers (~40k elements).
- Occupancy calendar cell states (morning/afternoon halves, stay per half, junction cut) and bar labels are precomputed per property in `computePropertyCells` (`src/lib/occupancy-cells.ts`, tested against the old per-day rule) and memoized; the render only reads arrays. The bar tooltip lives in its own store (`BarTipLayer`) so hovering never re-renders the grid.
- Every corner close "X" (dialog, sheet, alert confirmations, chat bubbles) uses `CORNER_CLOSE_CLASS` (`src/components/ui/corner-close.ts`, option C shape approved 08/11/2026, 12px bottom-left curve; theme-aware tone: `--foreground` at 9%/16% tab with the icon at 70%/100%, soft on light and visible on dark); never a local copy.
- Windows that open with the property cover photo on top (Pendências de Limpeza, Nova situação/Repetir, Pendências do imóvel, Concluir pendência, viewer de registro, Jornada da reserva) pass `cover` to `DialogContent`: the corner tab becomes the dark translucent veil (`CORNER_COVER_CLOSE_CLASS` 32px X / `CORNER_COVER_BACK_CLASS` 38px "‹ Voltar", decision of 13/11/2026). The Pendências de Limpeza list shows "‹ Voltar" (back to the board) instead of the X.
- When a window action is "go back" (drill-down from a list to one item inside the same window, or a wizard/step back), the corner tab becomes "‹ Voltar" IN PLACE of the X: pass `onBack` to `DialogContent` (`CORNER_BACK_CLASS`, `src/components/ui/corner-close.ts`, rule of 11/11/2026); never a loose "Voltar" button in the body or footer, and never a second window stacked on top. The X returns on the list/first step. Financeiro/Serviços/Limpeza lists open a lançamento in the same window via `CleaningDayDetailWindow` (`FinanceEntryDetail`).
- Card expansion never outlives the screen: a Dashboard window (`KpiCard`) keeps its own expanded id, cleared on close; `ArrivalGroup` drops the expanded id when the card leaves the list; a click right after closing the card menu or the revert confirmation is ignored (no ghost expand).
