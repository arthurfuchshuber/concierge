# Channex sync rules

- Channex history (bookings with guest contacts, Airbnb threads/messages, reviews) is backfilled idempotently by `backfillChannexHistory` (`src/lib/channex-history.server.ts`) into `property_reservations` (source `channex`, `guest_contacts`), chat tables and listing `normalized.reviews`; it is read-only on Channex so re-running never touches the Airbnb.
- Twin Airbnb listings of one physical unit each keep their OWN Channex property/room type/rate plan (so PriceLabs lists them separately) and resolve to the primary listing via `LISTING_ALIASES`; pairs live in the `channex_twin_links` table (any tenant; `PILOT_MAPPINGS` is only a fallback) and are read by `allSyncTargets`/`refreshListingAliases`, so each side's availability is the union of both units' bookings, re-pushed on every booking webhook.
- `linkTwinListing` gives the twin its own Channex unit, grants it on every PriceLabs API key, saves the pair and pushes the union calendar BEFORE re-mapping the listing; never share one room type between listings, since PriceLabs lists room types and would hide the twin.
- The dashboard occupancy calendar shows each twin listing as its own row (`twinRows` from `getOccupancyBoard`) mirroring the primary's stays, matching what PriceLabs lists.
- Channex non-booking entities (properties, room types, rate plans, channels, per-channel listing catalog) are synced by `syncChannexEntities` (`src/lib/channex-entity-sync.server.ts`) from the existing 1-min Channex cron and any non-booking webhook, throttled in DB; every entity is stored raw and diffed, and names follow `namingFor`: a property exclusive to one listing is titled with the internal name and its room type with the public title, shared properties keep the composite room title, so PriceLabs shows "[internal] - [public]" without manual prefixes — never sends ARI or creates mappings.
- Channex-connected listings are 100% API: `activeBookingNights` ignores `source='airbnb'` (iCal) rows; availability = Channex bookings (own + twin) + ConciergeIA manual blocks (`source='manual'`, `status='blocked'`) created via `manual-blocks.server.ts`, which re-pushes ARI for the property and every twin. Unconnected properties keep the legacy flow until connected.
- Airbnb operation mode is account-wide (`channex_account_settings.operation_mode`: `light` = read-only, `full` = ConciergeIA owns availability only, never prices); switching to `full` requires validated pricing-tool rates (`validatePricing`) first. The mode is open to every connected account (no pilot owner list); lists of Channex channels (twin suggestions, sender options) are always scoped to the account's own channels via `accountChannelScope`.
- Any enable/disable action on a listing is mirrored on its twin(s) (shared `property_id`), while every listing is always shown as its own row (AI list, calendar, inventory); `linkTwinListing` installs the Messages app on the new twin when the property's AI is on, so a new twin is never silent.
- The per-listing Airbnb AI switch drives the Channex Messages app (`syncMessagesApp` in `src/lib/channex-messages-app.server.ts`) on the listing's own and twin Channex properties: on = install/activate, off = deactivate; Channex is updated before the DB flag so the switch never lies.
- Connected-listing inventory (`getConnectedListingsInventory` in `src/lib/channex.functions.ts`) is always derived live from `property_listing_raw_data` + active `channex_twin_links` per owner, counting each twin listing individually; it is the basis for future per-listing billing and never touches plan prices.
- The AI sender identity on Airbnb is a per-listing preference (`switchListingSender`, applied to the whole twin group, stored as `channex_raw_records` entity `airbnb_sender_pref`); `sendChannexThreadMessage` posts directly to Airbnb with that account's OAuth token read live from Channex (never persisted), only after the Airbnb thread's listing matches the Channex thread, and falls back to Channex on any error — listings are never remapped, because Airbnb only lets the listing owner API-connect.

## Contas do Airbnb (onboarding multi-conta)
- Cada conta do Airbnb = um canal da Channex (`airbnb_accounts`). Desconectar NUNCA chama `PUT /channels/:id is_active:false`: desliga o app Messages (anúncios + gêmeos), pausa a sincronização (`sync_paused_at`, `paused_reason='account_disconnected'`) e arquiva os imóveis (`properties.archived_at`). Reconectar retoma só o que a desconexão pausou.
- O app Messages segue o anúncio ativo (`enableChat`/`disableChat` em `airbnb-accounts.server.ts`); a chave `airbnb_ai_enabled` só controla se a IA responde. Falha → `chat_pending_at` ("pendente de ativação do chat") com retentativa.
- Anúncio sem rate plan na Channex = "pendente de configuração"; o onboarding nunca mapeia rate plans nem envia ARI. Disponibilidade do modo Full só via `channex_ari_outbox`.
- Modo Leve/Full é da conta inteira, liberado para toda conta conectada; Full só é salvo após `validatePricing` com `checked > 0` e `missing === 0`.
- Sincronização de disponibilidade (`allSyncTargets`): gêmeos ativos + anúncios ativos de contas em Modo Full (nunca Leve) + `PILOT_MAPPINGS` só como reserva. Listas de canais da Channex sempre filtradas pelos canais da conta (`accountChannelScope`).
- Modo Full: anúncio vinculado só é mapeado no Airbnb via `confirmFullConnection` (`channex-full-connect.server.ts`) depois de 30 dias de diárias na unidade própria criada por `ensureUnit`; "mapeado" é lido ao vivo do canal, e o aviso fixo `FullConnectGate` ("Já conectei") só sai após o mapeamento seguro.
- Unidade nova do Modo Full nasce com carga inicial (`seedUnitCalendar`): fecha as noites do iCal real do Airbnb (se houver link) + reservas confirmadas e bloqueios manuais já no ConciergeIA e põe tarifa base só se a unidade não tiver nenhuma diária, para a ferramenta de preços sincronizar antes do "Já conectei"; seguro porque a unidade ainda não está mapeada.
- `syncRealAvailability` on a listing not yet mapped in the Airbnb channel also closes every night from the real Airbnb iCal when a link exists (aborting if it is unreadable); without a link it uses ConciergeIA's own reservations/blocks, since an unmapped unit never reaches Airbnb.
- Pre-existing Airbnb manual blocks are imported in `FullConnectGate` via `importIcalBlocks` (`src/lib/ical-blocks.server.ts`): only non-"Reserved" iCal events become `source='manual'` blocks (reservations arrive by API), and "Já conectei" stays disabled until every listing the user selected has been imported.
- Transitional guided migration: while the account has properties without an Airbnb listing, importing listings in `AirbnbAccountFlow` always switches to the bulk "De → Para" (existing properties first, leftovers become new properties), so imports never duplicate existing properties; remove once every property is synced.
- Availability never ignores iCal guest reservations (`source='airbnb'`, `status='confirmed'`) even for mapped listings, so the gap between mapping and API bookings arriving can't reopen dates; iCal `blocked` rows stay ignored (they mirror Channex). Booking webhooks re-sync only the affected Channex property and its twins.
- Full-mode unit creation (`ensureUnit`) is guarded by the `channex_unit_locks` row per property (10-min stale takeover), because concurrent callers (several users/tabs, retries on Channex 500) otherwise created duplicate Channex properties that PriceLabs listed.
- The blocking "Finalize a ativação" gate is shown only to the user recorded in `full_connect_conductors` (set by every import/link server fn); rows without a conductor fall back to everyone with access.
- Every active listing's Channex property (and twins) must have the Messages app: `createUnit` installs it on creation and `healMissingMessagesApps` (run by `syncChannexEntities`) installs any missing one, because without it Airbnb messages never reach ConciergeIA.
