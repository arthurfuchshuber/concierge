# Architecture rules

- Every floating surface must register with `global-overlay-store`; this keeps blur and outside-click order consistent across nested UI.
- Consecutive stays are reconciled from authoritative reservation dates; superseded open stages close without fabricating cleaning data.
- Panel entry resolves the authenticated user's own properties and active memberships independently of active-account RLS; this prevents a circular first-login lockout.- Every access grant, account creation, password change, company link or access removal must email the recipient (template `access-notice`); users are never left unaware of changes to their own access.
- Existing users from other companies are linked to a new company without overwriting their password; multi-company membership is supported.
- The landing guide is a separate copy (`vitrine-casa-charmosa`) owned by a technical demo user, auto-synced from the official `charmosa` guide on view (max every 2 min) with sensitive fields replaced by fictitious ones and no access gates; plan features come from the source owner.

- Channex ARI output always flows calendar diff → `channex_ari_outbox` → one batched call per kind → DB-counted 20/min limiter with retry (`src/lib/channex-ari.server.ts`); never call ARI endpoints directly or on a timer, so certification rules (delta-only, rate limits) hold.
- Channex bookings are read only via `booking_revisions` and each processed revision is ACKed idempotently (`channex_booking_acks`).
- Channex ARI outbox retries run from a 1-minute cron (`/api/public/cron/channex-ari-retry`) that only flushes due pending rows; never full-sync from a timer.
- Airbnb chat messages arrive as Channex `message` webhooks via the same queue and are handled in `src/lib/channex-messages.server.ts`; the guest-AI extension point (`src/lib/guest-ai/slot.server.ts`) is only consulted when the listing is resolved with certainty and its per-property `airbnb_ai_enabled` switch is on. With no AI implementation installed (old AI removed on 2026-11-01) every guest message is routed to the human queue (`needs_human`) with a push to the team.

- Airbnb listing data is ingested read-only from Channex into `property_listing_raw_data` (raw + normalized facts); only listings in `PILOT_LISTINGS` (`src/lib/channex-listing.server.ts`) are synced, so unvalidated properties stay untouched.
- Airbnb listings are never rate-plan mapped in Channex (ConciergeIA is not a PMS); mapping makes Airbnb hand pricing/calendar to Channex and blocks the calendar. Listing content not exposed by Channex (description, amenities) is read from the public Airbnb page in `fetchPublicListing` (`src/lib/channex-listing.server.ts`).
- Cross-channel guest identity resolves only against official reservations (reservation code, phone tail from Channex); conversations are linked to a reservation only by code (`src/lib/chat/conversation-link.server.ts`), never by name.
- Any platform delivery failure/block (Airbnb, WhatsApp) goes through `reportDeliveryFailure` (`src/lib/delivery-failure.server.ts`): forced handoff, `ai_alerts` row and push to property team plus SaaS admins, so blocked replies are never silent.
- Channex availability = listing window (`max_days_notice`) + confirmed reservations + manual blocks created in ConciergeIA; Airbnb iCal "Not available" rows are never used, since they mirror the Channex-controlled calendar and would lock it in a loop.
- A host message arriving from Airbnb via Channex pauses the AI on that thread (`pausePatch`, `src/lib/chat/pause.ts`); the pause/`airbnb_ai_enabled` controls are preserved so a future AI implementation never talks over a human.
- Every Channex API response and webhook is stored unfiltered in `channex_raw_records` (upsert by entity_type+channex_id) via `saveRawRecords` (`src/lib/channex-raw.server.ts`); structured columns are derived, so no Channex field is ever lost.

- Server-function bearer tokens come from `attachFreshSupabaseAuth` (`src/lib/fresh-auth-middleware.ts`), which refreshes the session shortly before expiry with a single shared refresh; the generated attacher is intentionally replaced so hourly token rollover never fails calls.
- Permission checks treat a failed lookup as "still loading" and keep the last known decision, never as denial, so transient network/session errors never lock screens into read-only.
- Subdirectories have their own `AGENTS.md`; read it before changing files there.
- The old AI implementation (orchestrator, prompts, RAG, memory, learning, assistant, escalations, proactive agents) was removed in full on 2026-11-01. Do not rebuild it piecemeal: the new LLM-first architecture plugs into `src/lib/guest-ai/slot.server.ts`. Conventional features that call the LLM gateway (translation, City Pulse, daily tip, guest documents, contract extraction, audio transcription) live in `src/lib/llm/`; the platform audit trail lives in `src/lib/audit/`.
- Cleaning totals and charts use one query observer without previous-period placeholder data, so date-filter transitions cannot mix periods or loading states.
- Window overlays (dialog, alert-dialog, sheet, drawer bases in `src/components/ui`) carry `data-dialog-overlay`; closing overlays never fade and `html` keeps `scrollbar-gutter: stable` (`src/styles.css`), so opening/switching windows never flashes the page behind. New windows must use these bases.
- Conversations escalated to a human never auto-open the full Atendimento window: they become `QuickChatBubbles` beside the floating button (stacked when several) that expand into an in-place mini-chat; only an explicit push click opens the full window.
- Playbook hides empty manually-editable optional rows (only `STANDARD_MANUAL_FIELDS` stay visible) and offers them via "Adicionar campo"; "Replicar" only shows on manually-edited rows, never on listing/scrap data such as house rules.
- The Gerencial page/menu item was removed (28/10/2026); `src/lib/executive.functions.ts` (director allowlist) is kept unused and no DB data was touched.
- Dashboard arrival lists requested together are merged client-side into one `listDashboardArrivalsBatch` call (permissions + stay reconciliation run once per batch); this keeps per-list query keys/optimistic updates while cutting mobile round-trips.

- Client access checks (`useAreaAccess`/`usePermission`) go through `accessBatcher.ts`, merging every check fired in the same 10ms per scope into one `getMyAccessDecisions` call, so a screen never pays the access lookup several times.
- The legacy iCal cron (`sync-airbnb-ical-30min`) was paused on 02/11/2026, but NOT every listing is API-connected: 32 properties (one owner) have no Channex connection and iCal is their only booking source (see project doc `descontinuacao-ical-auditoria-plano-2026-11-02`). Do not remove iCal code or data until each of them is covered by the API.
- The dashboard occupancy calendar keeps the full date range but renders only day columns near the viewport (column virtualization in `OccupancyPanel`, spacer cells keep the full scroll width) and uses no CSS scroll snap; rendering every day froze browsers (~40k elements).
- Realtime events (`LiveSync`) never refetch the shell queries in `NOT_LIVE` (admin flag, subscription, profile, admin customer lists), because they read tables outside the realtime publication; they refresh on tab focus/reconnect. A repeated `SIGNED_IN` for the same user with a healthy channel only updates the token, never re-subscribes the 38 tables.
- The landing copy sync (`landing-demo.server.ts`) rewrites a table only when its content differs from the official guide, so visits to the showcase do not generate writes or realtime events.
